| 关 | 内容 | 结果 |

**核心发现**：抖音 2026 现役扫码风控为「**页面加载 secsdk + bdms 官方 JS → 前端生成签名
cookie/头 → 才放行 get_qrcode**」的形态。纯 HTTP 客户端（含 TLS 指纹伪装）今天**过不了**
这一层。TSDK（2025）/ f2（2024）的纯 Python 口径实测已被拦——**A-1/A-3 风险部分实现**。

## 2. 关键事实（均为 2026-10-19 实测）

1. **域名迁移**：现役流程在 `sso.douyin.com`（`login.douyin.com/passport/web/` 为旧口径）；
   `sso.douyin.com` 根路径 200，`/login/scan_qr_login/` 返回登录页。
2. **aid/pageId**：登录页 SDK 初始化参数为 **aid=10006、pageId=31827**（TSDK 代码里的 6383 是旧口径）。
3. **bdms 是放行前提**：SDK glue 明确 `paths.include=["/get_qrcode"]`——不带 bdms 前端
   生成的签名，接口层直接降级返回登录页。
4. **纯 Python 复刻今天不够**：a_bogus 算法能算（G1 过），但风控看的不只 a_bogus——
   `__ac_signature` / `msToken` / `s_v_web_id` / `X-Secsdk-Csrf-Token` 等由官方
   bdms/secsdk JS 在浏览器端生成，Python 侧需逐个复刻且**抖音随时可改**。
5. **官方 JS 可在 Node 跑但工程代价高**：bdms.js 在 jsdom 可加载（说明不强制真实
   浏览器），但 init 挂起、API 面极小（仅 getReferer/init）、签名入口未明；
   且 bdms 是**版本化路径**（`stable/1.0.1.15/bdms.js`），更新即失效。

## 4. curl_cffi 依赖说明（协议 §8）

- **用途**：TLS 指纹伪装的基础 HTTP 客户端（实测可穿过抖音前两层风控：裸 curl 被
  `非法应用` 拦，curl_cffi Chrome 指纹 + session cookie 进到 4031 层）。即便登录改走
  R1/R2，**采集阶段**（收藏表情列表/文件下载）仍计划用 curl_cffi + a_bogus 复刻
  （f2 的 Python 复刻对普通接口仍有效，失败的是登录页最高风控接口）。
- **许可证**：MIT（lsyc/curl_cffi，PyPI `curl-cffi`）。
- **落点**：`pyproject.toml` `[project].dependencies`（人工 2026-10-19 授权，
  参照 BL-17 口径，限 curl_cffi 一项）。

## 7. 登录入口真机修正：sso.douyin.com 浏览器层全部重定向（2026-10-20，更新 §2/§5 口径）

**§2 的 curl 层结论在浏览器层不成立**。2026-10-20 用户真机报障「二维码不出现」，
QWebEngineView 实测复验（请求拦截 + DOM 采集 + 截图，诊断三轮）：

| 实测项 | 结果 |
| --- | --- |
| sso 四入口（`/login/`、`/login/scan_qr_login/`、`/login/?service=…`、`/?type=2`） | 浏览器里**全部前端重定向**到 `www.douyin.com/jingxuan`，get_qrcode 0 条 |
| 对照：curl 层 | 四入口均 200 + 登录页 HTML（§2 结论的来源）——**curl 不执行 JS，看不到重定向** |
| 主站路线（修正后） | 加载 `www.douyin.com` → JS 点「登录」→ 扫码弹层出现，`passport/web/get_qrcode/` + `check_qrconnect/`（轮询）全链路发出，二维码 178×178 渲染成功 |
| 移动 UA 直开 sso（对照） | 重定向 `/home`、无弹层——劣于桌面主站路线，弃用 |
| UA 对照 | QtWebEngine 默认 UA 与真 Chrome UA 行为一致——**重定向与 UA 无关**，是入口选择问题 |

**教训登记**：入口 URL 这类「浏览器行为强依赖」的选择，curl 层 200 不算数，
必须在目标运行环境（QWebEngineView）里复验。EM-005-B 的「R2 已验证」口径
据此修正为「R2 路线成立，但入口为主站 + 自动点登录」。

修复见 `def36e0`（RUN-20261020-005）；诊断截图与 JSON 留档于临时区
