## 2. spec 全文（`build/emoji-migrator.spec`，不入库）

```python
# -*- mode: python ; coding: utf-8 -*-
"""EM-006 发布版打包 spec：单文件 + 无控制台（onefile + windowed）。

⚠️ 本文件**不入库**（``.gitignore`` 忽略 ``*.spec`` 与 ``build/``，既定设计）——
耐久真相源是 ``docs/07-打包发布与验证.md``（逐行收录本文件全文）。改这里必须同步
改那份文档，否则干净签出无法复现本构建。

构建命令（仓库根，Git Bash；从仓库根跑，``--distpath``/``--workpath`` 相对仓库根）：

    .venv/Scripts/python.exe -m PyInstaller build/emoji-migrator.spec \
        --noconfirm --clean --distpath dist --workpath build/work

产物：``dist/把我的表情还回来.exe``（单文件、windowed 无控制台黑框）。
实测版本：PyInstaller 6.22.3 + PySide6 6.12.0（构建明细见 docs/07）。

入口说明：PyInstaller spec 的 ``scripts`` 只接受**脚本文件**，不支持
``module:function`` 入口语法，故 WebEngine 新前端的入口落地为
``src/emoji_migrator/webui.py``——该模块末尾的 ``__main__`` 守卫即
``raise SystemExit(main())``。旧版 ``gui.py`` 仍保留给兼容调用，但不作为发布入口。
"""

from pathlib import Path

from PyInstaller.utils.hooks import collect_data_files, copy_metadata

#: ``SPECPATH`` 是 PyInstaller 注入的 spec 全局：本 spec 所在目录（build/）。
#: 仓库根在其上一级。用绝对路径锚定，避免依赖运行时的 cwd。
_BUILD_DIR = Path(SPECPATH).resolve()
_PROJECT_ROOT = _BUILD_DIR.parent

#: 随包数据（验收「ffmpeg 等资源正确内嵌」）：
#:
#: 1. 图文指引截图（三端各 step1~3.png）。``config.PACKAGE_ROOT`` 在打包后指向
#:    PyInstaller 解包目录 ``_MEIPASS``，``emoji_migrator/guides/<平台>/stepN.png``
#:    的路径因此天然成立，GUI 无需任何打包分支代码；
#: 2. ``imageio_ffmpeg`` 自带的 ffmpeg 二进制。它**不在** PyInstaller 默认分析
#:    路径里（src 无人 import 它，只经 imageio 间接使用），必须显式收集，
#:    否则 ``get_ffmpeg_exe()`` 在 exe 里失效；
#: 3. ``imageio`` 的 dist-info 元数据。imageio 在 import 时就用
#:    ``importlib.metadata.version("imageio")`` 取自身版本（其 ``__init__.py``
#:    第 21 行），冻结后 bundle 里没有 dist-info 会直接
#:    ``PackageNotFoundError``——自检实测踩过，必须随包带上元数据，
#:    否则「资源就绪」不成立；
#: 4. 第三方许可证清单 → exe 解包目录内 ``THIRD-PARTY-LICENSES/``（PySide6 LGPL
#:    分发义务，BL-11）；
#: 5. QtWebEngine 运行资源（RUN-20261019-006 积压 #5，2026-10-20 人工授权
#:    ``build/`` 白名单补齐）：PyInstaller 6.22.3 的 QtWebEngine hooks 在 Windows
#:    上 dry-run 实测**只收翻译 ``.qm``**，三类关键资源一个不收，缺一登录窗
#:    即白屏/崩溃——① ``QtWebEngineProcess.exe``（渲染子进程）② ``resources/``
#:    的 pak / icudtl / v8 快照（**只收 release 必需 5 件**，devtools 与
#:    ``*.debug.*`` pak 合计约 90 MB，发布无用不收）③ ``Qt6WebEngineCore.dll``
#:    + ``Qt6WebEngineWidgets.dll``。目标布局与 PySide6 wheel 一致
#:    （``PySide6/`` 平铺 DLL 与子进程、``PySide6/resources/`` 收资源），
#:    QtWebEngineCore 运行时按自身所在目录定位这两处。
datas = [
    (str(_PROJECT_ROOT / "src" / "emoji_migrator" / "guides"), "emoji_migrator/guides"),
    (str(_PROJECT_ROOT / "src" / "emoji_migrator" / "webui"), "emoji_migrator/webui"),
    *collect_data_files("imageio_ffmpeg"),
    *copy_metadata("imageio"),
    (str(_PROJECT_ROOT / "docs" / "licenses"), "THIRD-PARTY-LICENSES"),
]

#: QtWebEngine 资源与二进制的来源定位（见 datas 注释第 5 条）。
import PySide6  # noqa: E402  （spec 在 venv 内执行，PySide6 可直接定位）

_PYSIDE6_DIR = Path(PySide6.__file__).resolve().parent

#: release 必需的 WebEngine 资源（不含 devtools / debug pak，见 datas 注释第 5 条）。
_QTWEBENGINE_RESOURCES = (
    "icudtl.dat",
    "qtwebengine_resources.pak",
    "qtwebengine_resources_100p.pak",
    "qtwebengine_resources_200p.pak",
    "v8_context_snapshot.bin",
)

datas += [
    (str(_PYSIDE6_DIR / "resources" / name), "PySide6/resources")
    for name in _QTWEBENGINE_RESOURCES
]

#: 渲染子进程 + WebEngine 核心/控件 DLL（目标布局镜像 wheel：PySide6/ 平铺）。
binaries = [
    (str(_PYSIDE6_DIR / "QtWebEngineProcess.exe"), "PySide6"),
    (str(_PYSIDE6_DIR / "Qt6WebEngineCore.dll"), "PySide6"),
    (str(_PYSIDE6_DIR / "Qt6WebEngineWidgets.dll"), "PySide6"),
]

#: ``imageio`` / ``imageio_ffmpeg`` 是 pyproject 声明的运行时依赖（EM-003 的
#: wxgf→GIF 链路需要），现在打进去做资源就绪。PySide6 由 PyInstaller 6.22.3
#: 自带 hook（``hook-PySide6*.py`` / ``hook-shiboken6.py``）处理，无需手工列举。
#: ``emoji_migrator.compress`` 是 EM-001 定义的 9 模块之一，但 GUI 链路
#: （gui → cli → sniff/normalize/dedupe/guard）不 import 它——不显式声明，
#: 冻结后 ``import emoji_migrator.compress`` 会 ModuleNotFound（自检实测踩过）。
#: 其余子模块均沿依赖链自然进入 bundle。
#:
#: ``curl_cffi`` 是 EM-005 的运行时依赖（MIT）。**必须显式声明**，两个理由：
#: 1. 它有**函数内延迟 import**（``collect_flow._init_network_errors`` 里的
#:    ``from curl_cffi.requests import exceptions``）——延迟 import 对
#:    PyInstaller 的静态分析不可见，只靠 ``douyin_collect`` 顶层的 import
#:    不够稳；
#: 2. 冻结后缺它会让「采集抖音」整条链路在 exe 里 ModuleNotFound，
#:    而 GUI 启动时不会报错（只在点采集按钮时才炸）——最难查的那种。
#: ``collect_flow`` / ``webp_gif`` 同理显式列出：前者是编排层入口，
#: 后者由 collect_flow 顶层 import 自然带入，列出只为自证。
#:
#: EM-003（微信表情解密，2026-10-20）新增的 5 项，**每一个都有必须显式声明的理由**：
#: 1. ``emoji_migrator.wxcollect`` —— 在 ``cli.py`` 与 ``gui.py`` 里**都是函数内
#:    延迟 import**（``_collect_weixin`` / ``_WeixinExportThread.run``），
#:    延迟 import 对静态分析不可见；只靠 ``cli`` 顶层不 import 它就会漏。
#:    缺它的症状极隐蔽：GUI 启动完全正常，只有点「导出微信表情」才 ModuleNotFound。
#: 2. ``emoji_migrator.wxscan`` —— 内存只读扫 seed（ctypes + AES）。
#:    它 import ``emoji_migrator.guard``（只读 API 白名单唯一真源），也须同包。
#: 3. ``emoji_migrator.wxdecrypt`` —— AES 解密 + 容器切分。
#: 4. ``emoji_migrator.wxdir`` —— 微信目录探测（winreg 只读）。
#: 5. ``Crypto.Cipher.AES`` —— **必须显式声明**。
#:    原因分两层：
#:    (a) 静态分析：``wxdecrypt`` / ``wxscan`` 里的 ``from Crypto.Cipher import AES``
#:        写在**函数体内**，PyInstaller 的模块扫描能覆盖到，但显式声明可确保
#:        ``Crypto`` 包一定进入分析图；
#:    (b) **C 扩展进包靠的是 hook，不是 hiddenimports**——
#:        ``_pyinstaller_hooks_contrib/stdhooks/hook-Crypto.py`` 会把
#:        ``Crypto/Cipher/_raw_aes.pyd``、``_mode_cbc.pyd`` 等**动态库**
#:        作为 ``binaries`` 收进包内 ``Crypto/Cipher/`` 子目录
#:        （pycryptodome 的 loader 要求它们在包目录里，不能放外面）。
#:        **hook 的触发前提是 ``Crypto`` 被静态分析到**——所以 (a) 是 (b) 的开关。
#:    实测旧包（EM-005-D 时期，尚无微信模块）里 ``Crypto`` 字符串**命中 0 次**，
#:    证明此前**从未把 pycryptodome 打进过包**——本项是新增依赖，
#:    不显式声明就会在 exe 里「点导出微信表情才炸」。
hiddenimports = [
    "imageio",
    "imageio_ffmpeg",
    "emoji_migrator.compress",
    "curl_cffi",
    "curl_cffi.requests",
    "emoji_migrator.collect_flow",
    "emoji_migrator.webp_gif",
    "emoji_migrator.wxcollect",
    "emoji_migrator.wxscan",
    "emoji_migrator.wxdecrypt",
    "emoji_migrator.wxdir",
    "Crypto.Cipher.AES",
]

#: 刻意**不开 UPX**（``EXE(upx=...)`` 默认即为 False，这里显式写明意图）：
#: UPX 会弄坏 Qt DLL 且加重杀软误报。应用图标使用设计稿产出的多尺寸 ICO。
#: ``block_cipher`` 已废弃，不写。
noarchive = False

a = Analysis(
    [str(_PROJECT_ROOT / "src" / "emoji_migrator" / "webui.py")],
    pathex=[str(_PROJECT_ROOT / "src")],
    binaries=binaries,
    datas=datas,
    hiddenimports=hiddenimports,
    hookspath=[],
    hooksconfig={},
    runtime_hooks=[],
    excludes=[],
    noarchive=noarchive,
    optimize=-1,
)
pyz = PYZ(a.pure)

#: Analysis 后过滤（2026-10-20 实测）：hooks-contrib 2026.8 的 QtWebEngineCore
#: hook 会把 ``PySide6/resources/`` **整目录**收进 bundle（含 devtools 与
#: ``*.debug.*`` 变体，合计约 90 MB——B 包「hook 只收 .qm」的口径在当前 hook
#: 版本下已不成立，但 hook 不收子进程 exe 与 DLL 仍成立）。发布版只保留
#: release 必需资源，按目标路径过滤，不触碰任何其他资源。
def _drop_webengine_debug_junk(toc):
    return [
        entry
        for entry in toc
        if not (
            entry[0].replace("\\", "/").startswith("PySide6/resources/")
            and ("devtools" in entry[0] or ".debug." in entry[0])
        )
    ]


a.datas = _drop_webengine_debug_junk(a.datas)
a.binaries = _drop_webengine_debug_junk(a.binaries)

exe = EXE(
    pyz,
    a.scripts,
    a.binaries,
    a.datas,
    [],
    name="把我的表情还回来",
    icon=str(_PROJECT_ROOT / "design-prototype" / "assets" / "app-icon" / "app-icon.ico"),
    debug=False,
    bootloader_ignore_signals=False,
    strip=False,
    upx=False,  # 见文件头：UPX 弄坏 Qt DLL + 杀软误报，明确关闭
    runtime_tmpdir=None,  # onefile：None = 解包到 %TEMP%（首次启动偏慢属正常）
    console=False,  # windowed：无控制台黑框（验收 5）
    disable_windowed_traceback=False,
    argv_emulation=False,
    target_arch=None,
    codesign_identity=None,
    entitlements_file=None,
)
```

## 4. 诊断自检（build/selftest_entry.py）

对**打出来的 bundle** 做资源就绪验证（console 构建才能拿到 stdout）：全部子模块
import、`imageio_ffmpeg.get_ffmpeg_exe()` 存在且 `ffmpeg -version` 退出码 0、
三套指引截图随包存在、GUIDES 键集合 == 真实目标平台值集合，并打印 bundle 内可见
的第三方顶层包名（供 `docs/licenses/NOTICE.md` 核对）。

```bash
# 第一步：捕获 exe 原始输出（GBK/cp936，原因见下方说明）
./build/diag/emoji-migrator-selftest.exe > selftest-gbk.txt
# 第二步：转码为 UTF-8 再存档（仓库 UTF-8 标准）
.venv/Scripts/python.exe -c "from pathlib import Path; p=Path('selftest-gbk.txt'); p.write_text(p.read_bytes().decode('gbk'), encoding='utf-8')"
```

> **编码说明（2026-10-15 独立审核整改后订正）**：exe 的 stdout 固定走系统本地
> 代码页（cp936/GBK）。本文档曾记载「加 `PYTHONUTF8=1` 即可输出 UTF-8」——
> **对冻结 exe 不成立**，审核实测：PyInstaller 6.22.3 onefile 引导进程不把父
> shell 的 `PYTHON*` 变量传给子进程（`PYTHONHOME=/nonexistent` 运行不崩；
> `PYTHONVERBOSE` / `PYTHONUTF8` / `PYTHONIOENCODING` 均无效）。`PYTHONUTF8=1`
> 只对**源脚本**（venv python 直跑 `build/selftest_entry.py`）有效；bundle 证据
> 必须来自 exe，故采集后必须转码。转码前先断言内容完整（4 行 `PASS:` +
> `SELFTEST-OK`、无 `FAIL:`）再落盘。

完整输出存档：`docs/em006-packaging-evidence/selftest-output.txt`（UTF-8）。
本目录同时存抖音指引截图证据（`guide-douyin*.png`）、发布 exe 真机运行截图

t=0 启动 → **t=2s onefile 解包完成**（_MEI 目录 238 文件）→ **t=5s 子进程创建窗口**

窗口在子进程上——自动化探活必须按 `ParentProcessId` 找子进程，盯父进程会误判「无窗口」。

## 7. 抖音指引截图复现

`fixtures/generate_guide_screenshots.py`（EM-004）不在 EM-006 白名单，故抖音截图
生成器落在 `build/generate_douyin_guides.py`（gitignored；逻辑要点如下，可复现）：

1. `QT_QPA_PLATFORM=offscreen` 先于 PySide6 import；offscreen 字体库为空时加载
   系统中文字体（msyh.ttc/simhei.ttf/simsun.ttc 候选，同 EM-004 手法）；
