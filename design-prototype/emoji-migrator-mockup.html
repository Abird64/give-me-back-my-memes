📐 设计说明 / 重构思路（点击展开）

1. 核心模型：从「三步向导」改为「相册式」

  • 原向导把微信导出 / 抖音采集（本质是获取来源）塞进第 2 步「选平台」页，逻辑错位。
  • 新模型分三阶段：导入三端 → 相册管理 → 选择导出。来源采集归到「导入」，平台选择只出现在「导出」。
  • 相册是中心：用户导入后统一分类、自由多选，不再被线性流程绑死。

2. 去掉「质量档位」假控件

  • 原代码明确「当前版本不做压缩，档位仅作记录」（EM-010 已下线档位常量）。留着误导用户，故删除。
  • 导出信息改为真实可读内容：文件数、去重数、目标平台格式规则。

3. 视觉

  • 配色走 CSS 变量（设计令牌），便于后续换肤 / 适配深浅色。
  • 平台色身份化：微信绿 / QQ 蓝 / 抖音红，一眼区分来源。
  • 圆角卡片 + 柔和阴影 + 克制过渡动画（取自通用 UI 原则）。
  • 长文本省略号处理（搜索/标签不撑破布局）。

4. 落地边界（保持治理协议）

  • 本文件是规划原型，不是仓库源码，不改动 gui.py / src。
  • 落地时后端仍复用既有受测模块：cli._normalize_dir、qqdir、wxcollect、collect_flow，不重写业务算法。
  • 合规红线（9 个禁用 API）不变。
