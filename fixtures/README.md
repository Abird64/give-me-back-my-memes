# fixtures/

测试素材目录。

## 硬约束

**本目录不得提交任何用户真实表情文件。**

原因：
1. 用户表情属个人数据，公开仓库中出现即构成泄露；
2. 需求基线 §3 非目标 1、2 之外，隐私合规是公开发布的前置条件；
3. 真实表情文件的版权归属不清晰。

`tests/test_compliance.py` 的静态扫描覆盖 `src/`；本目录的「无真实文件」约束
由人工评审与 EM-004 的打包白名单共同保障。

## 允许放什么

| 类型 | 说明 |
| --- | --- |
| 程序生成的合成图 | 用 Pillow / `imageio` 现画的色块、棋盘格、渐变 |
| 公共领域素材 | 明确标注来源与许可（如 Kenney.nl CC0、公版图库） |
| 畸形/边界样本 | 手写的截断文件、错误后缀，用于验证嗅探的 mismatch 分支 |

## 生成方式（EM-002 已交付）

合成素材由脚本现生成，**不入库二进制**（避免仓库膨胀与许可风险）：

```bash
.venv/Scripts/python.exe fixtures/generate_fixtures.py          # 默认写到 _out/synthetic/
.venv/Scripts/python.exe fixtures/generate_fixtures.py -o <目录> # 指定输出目录
```

脚本名：`generate_fixtures.py`（Pillow 合成，全程现画，不读取任何真实表情）。

### 分布参数（与本机实测对齐）

| 真实格式 | 数量 | 说明 |
| --- | --- | --- |
| GIF | 49 | 全部多帧，全部以 `.jpg` 命名 → **全部错乱** |
| JPEG | 94 | 全部以 `.jpg` 命名 → 后缀正确，**不计入错乱** |
| PNG | 3 | 以 `.jpg` 命名 → **错乱** |

合计 **146** 个，后缀错乱 **52** 个（= 49 GIF + 3 PNG），动图 **49** 个。
另含：超大尺寸 ≥1（1018×1024）、超大体积 ≥2（2300 KB 以上）、重复样本 9 个。

### 输出目录为什么是 `_out/synthetic/`

工作包建议写到 `fixtures/` 的子目录，但 `.gitignore` 里**没有** `fixtures/synthetic/`
的规则，而 `.gitignore` 不在 EM-002 的写入白名单内、不得修改。写到那里会产出
上百个待提交的二进制文件，与本文件「合成素材不入库」的原则冲突。
**入库的是脚本，不是它的产物**；`_out/` 已被 `.gitignore` 忽略，天然满足要求。

### 重复样本的两种构造（重要）

9 个重复样本分成两类，**这是刻意的**：

- **逐字节复制**（6 个）：最朴素的重复；
- **像素相同、字节不同**（3 个）：GIF 只改帧时长、PNG 多写一个文本块。

第二类是验收标准「动图按**像素内容**哈希，非文件字节哈希」的可判定形式。
若所有重复都逐字节相同，那么把感知哈希换成 `md5(path.read_bytes())` 也能全部命中——
那条验收标准就**测不出来**（突变实验 M4 已验证：本包夹具下 M4 会让 15 个测试变红）。

同理，每个样本都叠了一层由种子决定的**高对比度黑白方块阵**（`_identifier`）。
纯噪声样本缩到 dHash 的 9×8 采样后信息被平均掉，两两距离可能只有 4（实测
`gif_006/010/030/038` 恰好撞在阈值上被误判成重复），加了方块阵后
唯一样本之间的最小距离为 12，与阈值 4 有充足余量。
